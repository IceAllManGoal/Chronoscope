# frontend

**Каталог пока пуст — и это осознанное состояние, а не незавершённая работа.**

В 0.0.2 появился первый интерфейс, но он лежит **не здесь**: базовая страница —
обычные HTML, CSS и JavaScript в [`core/chronoscope/web/`](../core/chronoscope/web/),
и отдаёт её сам Core по `/ui`. Решение и его издержки — [ADR-0012](../docs/decisions/0012-web-page-served-by-core.md).

Причина разделения: страница 0.0.2 не имеет ни одной из задач, ради которых
выбирался стек ниже. §77 просит список событий с пагинацией, фильтрами и
деталями одного события — это таблица и панель подробностей, ни виртуализации,
ни графиков, ни графа. Ставить ради этого второй toolchain (Node, npm, Vite, шаг
сборки в CI и генерируемые файлы в репозитории) означало бы строить
инфраструктуру заранее, против чего прямо направлены §65 и §70.

## Что здесь появится

Стек остаётся предварительно зафиксированным (§55):

```text
TypeScript
React
Vite
```

Он выбран под сложные задачи интерфейса: виртуализированный timeline, графики,
отображение графа процессов. То есть он понадобится примерно к 0.1.0 «Timeline»
(§77), и тогда базовая страница будет заменена: переиспользуются не её файлы, а
вызовы API Core.

Решение о desktop-обёртке (локальный web UI, WebView2 host или другой shell)
по-прежнему **сознательно не принимается** (§55). Отдельно от него решён только
вопрос «чем отдаётся страница» — Core, см. ADR-0012.

## Что важно помнить при проектировании UI

- UI не читает SQLite напрямую — только через API Core (§81, инвариант 10). Базовая страница соблюдает это по построению: она живёт на том же origin, что и API, и обращается к `/api/v1`;
- данные из API вставляются в разметку только через `textContent`. Имена процессов и командные строки приходят из внешнего мира, и собирать из них HTML значило бы позволить источнику событий выполнять код в интерфейсе наблюдателя — в `core/tests/test_web_page.py` это проверяется;
- порядок работы проекта: сначала data pipeline, потом интерфейс. Главные риски Chronoscope — корректность event model, стабильность сбора, объём данных, идентичность процессов, ordering, storage, privacy и производительность запросов, а не внешний вид (§56).

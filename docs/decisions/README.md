# Architecture Decision Records

ADR фиксируют существенные архитектурные решения Chronoscope: контекст, само решение и его последствия. Правило §81 спеки: архитектурные инварианты не нарушаются без отдельного ADR.

Заголовки разделов — русские, структура соответствует шаблону из §53 спеки (`Status` / `Context` / `Decision` / `Consequences`).

## Когда нужен ADR

ADR обязателен, если изменение затрагивает:

- архитектурные инварианты (§81);
- контракт между Agent и Core, включая JSON-схемы;
- схему БД;
- формат идентификаторов;
- модель времени;
- модель приватности;
- лицензирование или правила участия;
- зависимости (особенно Windows hooks, packet capture, kernel drivers, native DLL и elevated services).

Для мелких изменений ADR не нужен.

## Как добавить

1. Скопировать [`template.md`](template.md).
2. Назвать файл `NNNN-kebab-case-name.md`, где `NNNN` — следующий свободный номер (четыре цифры).
3. Заполнить контекст, решение и **последствия — включая отрицательные**. ADR без честно описанных издержек бесполезен.
4. Добавить строку в таблицу выше.
5. Если ADR отменяет предыдущее решение — не удалять старый файл, а поменять его статус на «Заменено ADR-NNNN».

## Статусы

```text
Предложено     обсуждается, решение ещё не принято
Принято        действует
Заменено       отменено другим ADR
Устарело       перестало быть актуальным без прямой замены
```

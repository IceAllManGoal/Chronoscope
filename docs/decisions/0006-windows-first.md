# ADR-0006: Windows как первая платформа

## Статус

Принято. Дата: 2026-09-18

## Контекст

Chronoscope задуман как инструмент наблюдения за историей компьютера. Платформы различаются тем, какие источники событий доступны и насколько глубоко в систему можно смотреть: Windows Event Log, ETW, Sysmon, WMI, реестр, службы, драйверы не имеют прямых аналогов на других системах.

Попытка сразу поддерживать Windows, Linux и macOS означала бы проектирование слоя абстракции до того, как появился хотя бы один работающий источник. §80 спеки называет это прямой дорогой к premature abstraction.

## Решение

Первая и единственная платформа в 0.0.1 — **Windows**. Agent реализуется как Windows-native процесс на C#/.NET (§8.2).

Кросс-платформенность не отвергается, а откладывается: Core с самого начала не зависит от Windows API (§81, инвариант 1), поэтому будущие `Chronoscope.Agent.Linux` и `.MacOS` не потребуют переписывания ядра.

Разработка ведётся и тестируется на Windows; CI ориентирован на Windows-раннеры.

## Последствия

**Положительные:**

- можно использовать платформенные механизмы напрямую, без слоя абстракции;
- C#/.NET даёт удобный доступ к Windows API, Event Log и ETW, сильную типизацию и хороший async runtime (§8.2);
- Agent в будущем оформляется как Windows Service без изменения архитектуры;
- тестовое окружение совпадает с продакшн-окружением.

**Отрицательные и принятые издержки:**

- проект в 0.0.1 бесполезен для пользователей Linux и macOS, а также не запускается в CI на Linux-раннерах;
- Core придётся сознательно удерживать платформенно-нейтральным: любая утечка Windows-специфики потребует рефакторинга перед появлением второго Agent'а. Это дисциплина, а не то, что проверяет компилятор;
- часть кода Agent невозможно юнит-тестировать без Windows-окружения, поэтому тесты коллекторов отделены от тестов Core (§48);
- Docker не помогает: Agent обязан взаимодействовать с Windows host, поэтому контейнеризация не является полезной целью сама по себе (§64).

# ADR-0007: API только на loopback

## Статус

Принято. Дата: 2026-09-18

## Контекст

Core предоставляет HTTP API, которому Agent доставляет события. Привычное решение — слушать `0.0.0.0`, чтобы «на всякий случай» обеспечить доступ извне: с другого устройства в домашней сети, для отладки, для будущего multi-host сценария.

Chronoscope собирает чувствительные данные о работе компьютера: имена процессов, пути, командные строки, SID пользователя. §37 прямо признаёт, что командная строка может содержать токены, пароли, API keys и приватные пути. Инструмент, отдающий это по сети без аутентификации, превращается в канал утечки — ровно то, чего продукт должен избегать (§6.2, privacy by default).

Дополнительно: §5.3 исключает удалённое администрирование, а §74 — remote agents из ближайших версий. Значит, внешний доступ не нужен не «пока», а по самому определению продукта на этом этапе.

## Решение

Core слушает **только** `127.0.0.1`, никогда `0.0.0.0` (§33).

Минимум для 0.0.1:

```text
loopback-only bind
configurable port
request size limits
input validation
```

Сверх того:

- нет API для удалённого выполнения кода;
- нет endpoint'а для произвольного SQL;
- нет shell endpoint;
- путь к БД приходит только из конфигурации и никогда от HTTP-клиента;
- чувствительные данные минимизируются в логах (§66).

Локальный shared secret между Agent и Core **не** вводится в 0.0.1 и запланирован позже (§33).

## Последствия

**Положительные:**

- события и командные строки не покидают машину;
- отсутствие внешней поверхности атаки: с другого хоста API недостижим в принципе, а не «защищён паролем»;
- соответствует обещанию privacy by default (§6.2) и упрощает объяснение продукта;
- нет необходимости в transport encryption и управлении ключами на этом этапе.

**Отрицательные и принятые издержки:**

- отладка с другого устройства невозможна без туннеля; это осознанное ограничение;
- multi-host сценарии (несколько машин, поддержка специалистом) потребуют отдельного решения и ADR. При их появлении bind на loopback придётся пересматривать вместе с аутентификацией;
- отсутствие аутентификации на loopback означает, что **любой локальный процесс** под тем же пользователем может читать собранные события и отправлять события через ingest. Это принято для 0.0.1 и зафиксировано в [`SECURITY.md`](../../SECURITY.md);
- соблазн «временно» открыть bind придётся consciously отклонять: такое изменение требует нового ADR, а не правки конфигурации по умолчанию.

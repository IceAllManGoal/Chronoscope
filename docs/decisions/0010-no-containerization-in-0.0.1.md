# ADR-0010: Не контейнеризировать в 0.0.1

## Статус

Принято. Дата: 2026-09-18

## Контекст

При планировании структуры репозитория рассматривался `docker-compose.yml` в корне как привычный элемент современного проекта. Предполагалось, что он «на будущее» поднимет Core.

Против этого три независимых обстоятельства:

1. **§74** явно выносит `Docker deployment` за пределы 0.0.1, а §64 указывает, что Docker не обязателен: Agent взаимодействует с Windows host, поэтому контейнеризация не является полезной целью сама по себе.
2. **В 0.0.1 нечего оркестрировать.** Core — локальный Python-процесс на SQLite. PostgreSQL, ClickHouse, Redis и Kafka исключены из версии (§54, §74), frontend отсутствует. Compose-файл описывал бы один сервис, который и так запускается одной командой.
3. **Контейнеризация конфликтует с моделью безопасности.** Core обязан слушать только loopback ([ADR-0007](0007-local-only-api.md), §33). Внутри контейнера bind на `127.0.0.1` недостижим снаружи, поэтому для доступа Agent'а пришлось бы слушать `0.0.0.0` и полагаться на маппинг портов — то есть ослабить именно тот инвариант, который защищает чувствительные данные. Кроме того, Agent принципиально не контейнеризуется: это Windows-native процесс, которому нужен доступ к процессам, Event Log и ETW хоста (§8.1).

## Решение

`docker-compose.yml` и любые Docker-артефакты в 0.0.1 **не создаются**.

Запуск в dev-режиме — два процесса в двух терминалах (§63):

```text
Terminal 1:  python -m chronoscope
Terminal 2:  dotnet run --project agent/...
```

## Последствия

**Положительные:**

- структура репозитория отражает реальное состояние проекта: в ней нет файлов, которые ничего не делают;
- модель безопасности не размывается: bind на loopback остаётся безусловным правилом, а не настройкой, которую «для контейнера» приходится менять;
- никому не приходится разбираться, зачем нужен compose-файл, и поддерживать его в актуальном состоянии;
- dev-цикл короче: нет сборки образа и слоя маппинга портов между Agent и Core.

**Отрицательные и принятые издержки:**

- воспроизводимость окружения ниже: версии Python и .NET задаются документацией и, позже, lock-файлами, а не образом. Смягчение — `pyproject.toml` с зафиксированными зависимостями и требования к SDK в [`README.md`](../../README.md);
- «поднять проект одной командой» в смысле `docker compose up` не получится. Вместо этого появятся dev-скрипты в `scripts/`;
- при появлении реального сервиса, который нужно поднимать вместе с Core, решение придётся пересмотреть. Тогда же встанет вопрос о bind-адресе и способе доступа Agent к контейнеру — это потребует нового ADR, а не тихой правки compose-файла.

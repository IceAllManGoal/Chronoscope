# ADR-0001: Использовать monorepo

## Статус

Принято. Дата: 2026-09-18

## Контекст

Chronoscope состоит из компонентов на разных технологиях: Agent (C#/.NET), Core (Python), будущий frontend (TypeScript) и общий формальный контракт между ними в виде JSON-схем.

Контракт здесь — не деталь, а источник основных рисков проекта (§56): корректность event model, ordering, идентичность процессов. Если Agent и Core разойдутся в понимании `RawEvent`, ошибка проявится не как ошибка компиляции, а как молча испорченные исторические данные.

Вариант с отдельными репозиториями на компонент означал бы, что изменение схемы требует синхронных релизов в нескольких местах и что совместимость проверяется вручную. Это неприемлемо на этапе, когда контракт активно меняется (§72: до `1.0.0` проект развивается быстро).

## Решение

Проект ведётся как monorepo. Компоненты разделены каталогами:

```text
core/        Chronoscope Core (Python)
agent/       Chronoscope Agent (C#/.NET)
frontend/    будущий UI
shared/      JSON-схемы контракта и фикстуры, общие для Agent и Core
docs/        спека, архитектура, модель событий, ADR
scripts/     dev-скрипты
```

Общие JSON-схемы и фикстуры лежат в `shared/` и используются обоими компонентами без копирования.

## Последствия

**Положительные:**

- изменение контракта и его потребители меняются одним коммитом, а не серией синхронных релизов;
- общие фикстуры: Agent и Core тестируются против одних и тех же данных (§51, §58);
- одна история, один CHANGELOG, один номер версии для всей вертикальной системы;
- проще воспроизвести полный E2E-сценарий 0.0.1 (§75).

**Отрицательные и принятые издержки:**

- в репозитории сосуществуют разные toolchain'ы (Python, .NET, позже Node): CI должен запускать задачи выборочно, иначе любое изменение прогоняет всё;
- репозиторий растёт быстрее, чем рос бы репозиторий одного компонента;
- для внешних контрибьюторов, работающих только с Core, репозиторий выглядит крупнее необходимого;
- если однажды Agent и Core потребуют независимых циклов релизов с разными правами доступа, разделение станет оправданным — но этого не следует делать заранее.

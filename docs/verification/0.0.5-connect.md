# Проверка 0.0.5 «Connect» — 2026-10-10

**READY FOR RELEASE** по §77.3. Это готовность изменения к выпуску, не факт
публикации: main не изменён, tag и GitHub Release не созданы. Рабочая ветка —
`codex/connect-0.0.5`, база — `d3b73715331e4c6bbfdcb7104659134c49a0f056`.

## Реализация и архитектура

Добавлены наблюдаемые parent/child relationships, дерево потомков и события
с actor/subject ссылкой на экземпляр. Новых таблиц процессов или связей нет.
Доменный resolver проверяет host, boot, PID, время старта/выхода, исходные
actor references и конфликты; PID служит только поиском кандидатов.
`resolved` означает единственного совместимого кандидата среди прочитанных
наблюдений. Он не доказывает причинность и не означает полноты WMI.

Выбраны два новых endpoint: `/processes/{id}/relations` и `/tree`.
Для событий расширен общий `/events?entity_id=…`; отдельный related-events
endpoint дублировал бы пагинацию. Временное соседство не используется как связь.
Чтение relations/tree идёт в одном явном SQLite snapshot. Каждый следующий
HTTP-запрос может увидеть поздние Events; сохранённые Events не переписываются.

Дерево строится по уровням, с кэшем наблюдений на запрос, visited set и
пределами depth 5 / nodes 200 / lifecycle evidence 10000. Кандидаты читаются
пакетами, максимум 2000 IDs за поиск и 200 ключей за batch. Overflow не
позволяет разрешать связи по частичной истории и обозначается в ответе.
Evidence response ограничен 32 ссылками с полным счётчиком и признаком усечения.

Миграция 0003 добавляет два expression index для host/boot/JSON PID и parent PID.
Старый lookup нормализатора также использует консервативные проверки при новом
ingest. ProcessDetail сохраняет форму исторического контракта, перестаёт
скрывать локальные противоречия; текущая проверка связей принадлежит relations.

CLI: `process-relations <id>`, `process-tree <id> --depth 3 --max-nodes 200`,
`events --entity-id <id>`. UI поддерживает Event → Process → Parent/Child →
Tree → Related Events → Event и возврат. Фильтры/страница главного списка
сохраняются. Неизвестный родитель не становится фиктивной ссылкой.

Контракт и реальные примеры — [CONNECT_API](../CONNECT_API.md); аудит,
альтернативы и последствия — [ADR-0017](../decisions/0017-evidence-based-process-relationships.md).

Окружение: Windows 11 build 26200, Python 3.13.12, .NET 8 SDK; зависимости из
lockfile. TEMP/TMP направлены в собственный data/connect-temp, поскольку
системный TEMP недоступен для записи. Права системных каталогов не менялись.

  Базовый набор до работы — 386 passed. Финальный прогон включает unit,
  migration, repository, API и CLI integration; это один набор, не сумма
  отдельно повторённых тестов.
- Agent: **141 passed, 0 failed, 0 skipped**. Сборка: 0 warnings, 0 errors.
- `node --check core/chronoscope/web/app.js`: exit 0.
- Миграции: новая база до head, downgrade 0002/re-upgrade с сохранёнными Events,
  совпадение expression indexes модели/миграции, реальный EXPLAIN.
- **7/7 мутаций обнаружены assertion failures**, исходники восстановлены:
  PID без host/boot, игнорирование exit/start, скрытие конфликта, снятие visited,
  снятие node limit, временное соседство вместо entity relationship.
  [Машиночитаемый результат](0.0.5-mutations.json).

Регрессии Connect — [test_process_connections.py](../../core/tests/test_process_connections.py),

404, неверные ID/пределы — 422; широкое дерево/цикл сериализуются с причинами,
actor OR subject сохраняет порядок, фильтры и дедупликацию на страницах.
Поздний ingest, повторная доставка и restart проверяются с настоящей SQLite.
Race test записывает событие между чтениями и проверяет snapshot consistency.

Этот раздел фиксирует **локальные** результаты. GitHub CI необходимо сверять

## Измерения запросов

[Полный JSON с EXPLAIN](0.0.5-benchmark.json), воспроизводимый
[benchmark-connect.py](../../scripts/benchmark-connect.py). Детерминированные
1000/20000 Events: цепочка 4 уровней, 240 прямых детей, посторонний фон.
Каждая операция — первая выборка с новым connection/SQLite page cache и
семь повторов. **OS cache не сбрасывался**; первая выборка не означает
холодный диск. Показаны медианы семи повторов; данные не являются SLA.

| Events | Операция | До индексов, first / median ms | После, first / median ms | SELECT |
|---|---|---|---|---|
| 1000 | relations | 7.17 / 3.07 | 4.71 / 1.77 | 5 |
| 1000 | chain tree | 7.86 / 7.06 | 4.98 / 3.70 | 11 |
| 1000 | wide tree (200 узлов) | 13.94 / 14.84 | 13.10 / 11.48 | 4 |
| 20000 | relations | 45.85 / 42.27 | 5.09 / 1.72 | 5 |
| 20000 | chain tree | 100.36 / 97.44 | 4.53 / 3.72 | 11 |
| 20000 | wide tree (200 узлов) | 47.52 / 51.55 | 20.30 / 18.81 | 4 |

На 20000 Events с индексами: entity page median 1.684 ms, следующая страница
1.764 ms, временной фильтр 1.780 ms, actor-only 0.700 ms; по одному SELECT.
До индексов PID поиск шёл через `ix_events_type_timestamp`, с временным
DISTINCT. После — `ix_events_process_pid/parent_pid (host_id=?, boot_id=?,
<expr>=?)`. Временной фильтр/курсор entity page использует actor/subject
timestamp indexes. UNION dedup и финальная сортировка работают максимум
на двух потоках page limit+1 (до 2002 строк), а не всей истории процесса.
Повторная ссылка actor=subject и равные timestamps проверены репозиторными
и HTTP тестами. EXPLAIN для 1/2/200 ключей защищает группировку PID IN.

Цена индексов: bulk insert 20000 строк 271.803 → 366.496 ms. Это один sample,
не ingestion benchmark; время доставки/нормализации в него не входит.
SQL counts растут с уровнями, не числом узлов внутри одного уровня.
Индексы ограничивают область поиска, но жёсткий timeout исполнения SQLite
не вводился; лимиты относятся к объёму читаемых свидетельств/результатов.

## Adversarial review

Повторно проверены identity scope, reuse/overlap, exits до child, будущие
starts, missing boot, dangling/self actors, циклы, 240 детей, противоречащие
timestamps, поздняя/повторная доставка, malformed references и read/ingest race.
Исправлены два обнаруженных дефекта: конфликтный кандидат больше не выпадает
из сравнения при конфликте host/boot/PID; широкий PID OR заменён группировкой
IN, чтобы реальный план использовал scoped index. Добавлены регрессии.
Уточнены лимит evidence references, поведение старого ProcessDetail и текст
CLI для неизвестного родителя. Контракт history_limit_exceeded остаётся 500.

## Ограничения и следующие задачи

WMI может пропустить короткоживущие процессы и задержать доставку. Нет exit —
не доказательство жизни; нет ребёнка — не доказательство отсутствия запуска.
Неразличимые кандидаты остаются unresolved; конфликт старого actor может
сохранить conflicting даже при правдоподобном кандидате. Выборка всегда
`observation_complete=false`; `truncated=false` говорит только о лимитах запроса.
Таблиц процессов, backfill, causal inference, ETW и durable spool здесь нет.

Для 0.1.0 Timeline: сохраняемое состояние исследования (URL/история фильтров),
удобное объяснение evidence и отдельный явно обозначенный temporal context.
Отдельный backlog: измерение задержек/пропусков источников и heartbeat,
ETW evaluation, durable spool/retention, более крупные history benchmarks.
Они требуют собственных критериев и не маскируются готовностью Connect.

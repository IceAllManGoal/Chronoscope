# Dev-скрипты

PowerShell-скрипты для локальной разработки. Все запускаются из корня репозитория:

```powershell
pwsh scripts/<имя-скрипта>.ps1
```

| Скрипт | Назначение |
|---|---|
| `dev.ps1` | Поднимает Core и Agent в dev-режиме (§63): синхронизирует окружение, применяет миграции, открывает оба компонента в отдельных окнах |
| `test.ps1` | Прогоняет тесты Core и Agent (§58) |
| `reset-dev-data.ps1` | Удаляет локальные dev-данные Chronoscope из `data/` |

`docker-compose.yml` в репозитории нет: Chronoscope — локальный продукт, а Agent обязан быть Windows-native процессом ([ADR-0010](../docs/decisions/0010-no-containerization-in-0.0.1.md)).

## Коды возврата

Скрипты различают «не получилось» и «не запускалось»: молчаливый ноль кода возврата при непройденном тесте скрыл бы второе под видом первого.

| Код | `dev.ps1` | `test.ps1` |
|---|---|---|
| 0 | компоненты запущены, Core отвечает на `/health` | все запрошенные наборы прошли |
| 1 | Core не ответил за `-HealthTimeout` или не применились миграции | хотя бы один набор упал |
| 2 | не выполнено предусловие (нет окружения Core или .NET SDK) | не выполнено предусловие (нет окружения Core или .NET SDK) |

## Кодировка

`.ps1` записываются в **UTF-8 с BOM**, хотя общее правило проекта — UTF-8 без BOM ([`.editorconfig`](../.editorconfig)). Это не вольность: Windows PowerShell 5.1 читает скрипт без BOM в системной кодировке, и русский текст в нём превращается в мусор — скрипт падает на разборе ещё до первого оператора. `reset-dev-data.ps1` так и не запускался под 5.1, пока BOM не был добавлен. PowerShell 7 читает UTF-8 по умолчанию и BOM корректно пропускает, поэтому правило безопасно для обоих хостов.

`uv` скрипты ищут в PATH, затем в `core/.venv/Scripts`. Это не украшение: `uv` может быть не в PATH, а окружение уже готово, и падать из-за этого скрипт не должен. Если нет ни того, ни другого, `dev.ps1` работает через интерпретатор `.venv`, а `test.ps1` сообщает, что тесты Core не запускались.

## Запущенные процессы

`dev.ps1` открывает каждому компоненту своё окно: у обоих структурированные JSON-логи (§35), и в одном окне они перемешались бы. Окно остаётся открытым после завершения компонента — иначе причина падения исчезала бы вместе с окном.

Остановить компонент — `Ctrl+C` в его окне или закрытие окна. Полезно знать: если окно было снято принудительно (`Stop-Process`), дочерний процесс может остаться жить и держать порт. Тогда следующий запуск `dev.ps1` обратится к старому Core, и это будет выглядеть как «изменения не применились». Проверить, что ничего не осталось:

```powershell
Test-NetConnection 127.0.0.1 -Port 7342 -InformationLevel Quiet   # False — порт свободен
```

## Проверка самих скриптов

Скрипты проверяются запуском, а не чтением: `dev.ps1` — с `-DryRun` и затем вживую (Core отвечает на `/health`, Agent доставляет события), `test.ps1` — на обоих наборах, `reset-dev-data.ps1` — с `-WhatIf`.
